# tei-entity-reconciliation

> Turn raw NER output in a TEI corpus into clean **authority registers**, reconciled
> against external referentials (Wikidata), and rewrite the documents' `@ref` so every
> inline mention points at a stable register id.

A small, dependency-free pipeline (Python 3 standard library only) that takes TEI
documents already annotated by NER and produces TEI Publisher–ready authority files
for **9 entity types**: persons, places, organizations, works, events, artworks,
materials, techniques, and a chronology.

It was extracted from the [Grand Siècle](https://github.com/GrandSiecle) TEI Publisher
project to be reusable on any TEI corpus.

---

## What it does

```
TEI documents (NER already run: standOff defs + inline @ref)
      │
      ▼  1. extract_entities.py
cluster the surface forms into deduplicated authority entities
      │   (key = type + normalized label; OCR variants merged)
      ▼  2. reconcile_wikidata.py
match each cluster to a Wikidata QID — validated PER TYPE by properties
      │   (place→coords/GeoNames, person→dates/occupation, work→author…),
      │   period filter, notability score, confidence high/medium/low
      ▼  3. build_registers.py
write 9 TEI registers + id_mapping.csv (NER UUID → register id)
      │
      ▼  4. rewrite_refs.py
rewrite the documents' @ref: #pers-<uuid> → #person-000432
```

Uploading the result into a database (e.g. eXist-db / TEI Publisher) and reindexing
are **deployment concerns of the consuming application**, intentionally out of scope here.

---

## Why

NER tools emit per-document, per-mention identifiers (UUIDs). To get working
person/place/work indexes you need to (a) **deduplicate** mentions into canonical
entities across the whole corpus, (b) **reconcile** them to an external authority so
they carry stable identifiers and metadata, and (c) **re-point** the documents at those
canonical entities. This repo does exactly those three things, conservatively (no false
positives, no data corruption — see the invariants below).

---

## Requirements

- **Python 3.8+** — standard library only (`xml.etree`, `urllib`, `csv`…). No `pip install`.
- `curl` only for the optional eXist upload helper (kept in the consuming app, not here).
- Reconciliation step needs network access to the Wikidata API.

```
  import_curation.py      # team: import reviewer decisions into curation.csv

tests/
  run_tests.sh            # offline suite (no network, no deps)
  test_*.py               # unit tests (extract, reconcile, idregistry, curation, export/import,
                          #   rewrite_refs, validate_registers)
  test_pipeline.sh        # end-to-end extract→build→curate→lots→import→rewrite→validate
  validate_registers.py   # reusable health-check / QA tool
  test_wikidata_smoke.sh  # optional live API check

  registers/id_registry.csv   # COMMITTED, hand-maintained: stable id per entity (never reused)
  registers/curation.csv      # COMMITTED, hand-maintained: the team's curation decisions

```

Everything under `data/registers/` is regenerated by each build **except**
`id_registry.csv` and `curation.csv`: they are the project's memory, tracked by git
(`.gitignore` excludes the other CSVs) and must never be deleted.

By default the scripts assume the repo layout: inputs in `data/`, artifacts in
`build/ner/`, registers in `data/registers/`. **All of these are overridable** — see
[Configuration](#configuration).

## Quickstart (on the bundled sample)

```bash
# 1. extract entity clusters from the sample document
TEI_GLOB="examples/sample/data/sample_reconciled.tei.xml" NER_OUT=build/ner \
  python3 scripts/extract_entities.py

# 2. reconcile to Wikidata (network). Always set a contact (WMF politeness policy).
WIKIDATA_CONTACT="you@example.org" NER_OUT=build/ner \
  python3 scripts/reconcile_wikidata.py --types person,place

# 3. build the 9 registers + id_mapping.csv
NER_OUT=build/ner REGISTERS_DIR=data/registers CORPUS_NAME="My Corpus" \
  python3 scripts/build_registers.py

# 4. rewrite the document @ref using the mapping
python3 scripts/rewrite_refs.py --mapping data/registers/id_mapping.csv \
  examples/sample/data/sample_reconciled.tei.xml
```

On a real corpus, drop your `*_reconciled.tei.xml` files in `data/` and run the four
steps with the defaults (no env vars needed).

## The four steps

### 1. `extract_entities.py` — clustering
Reads each TEI file's `standOff` definitions **and** every inline `@ref` mention
(materials / techniques / dates only ever appear inline). Deduplicates by
`(type, normalized_label)`, merging OCR variants and accumulating source docs, mention
counts and the merged NER UUIDs. → `build/ner/entities_clusters.json` (+ `.csv`).

### 2. `reconcile_wikidata.py` — reconciliation
Queries the Wikidata API and **validates each candidate by the properties expected for
its type** to avoid false positives (a place must have coordinates/GeoNames, a person
birth/death or occupation, a work an author…). Adds a period filter (17th-c. corpus),
a notability score (sitelinks) and a `high/medium/low` confidence. **Resumable**: a disk
cache (`build/ner/wd_cache.json`) means re-runs only do what's missing. WMF-compliant
(descriptive User-Agent, `maxlag`, serial-ish requests).

```bash
python3 scripts/reconcile_wikidata.py [--min-mentions N] [--limit N] [--types t1,t2]
```

### 3. `build_registers.py` — registers
Writes the 9 TEI registers to `data/registers/` plus `id_mapping.csv`
(NER UUID → register id) and a reconciliation report. The Wikidata QID is **asserted
only for high/medium** matches; low ones are kept as a curation hint.

Register ids are **stable**: they come from `id_registry.csv` (lookup by
`(type, normalized label)`, then by overlap of NER UUIDs, else a new id — ids are
never reused), so adding documents to the corpus does not renumber existing entities.
The team's decisions in `curation.csv` are then re-applied on every build (see
[Team workflow](#team-workflow-incremental-curation)). The curated clusters are also
written to `build/ner/entities_registered.json`, the input of `export_lots.py`.

### 4. `rewrite_refs.py` — re-pointing the documents
Rewrites the inline `@ref` from NER UUIDs to register ids, **and rebuilds the
document's own entity lists** (`teiHeader` / `standOff`) with the same ids, so
header ↔ body joins keep working ([issue #1](https://github.com/Grand-Siecle/tei-entity-reconciliation/issues/1)).
The invariants that keep the data safe:

1. **One list entry per register id.** The mapping is *many-to-one* (the deduplication
   merged several UUIDs into one register entry), so renaming `xml:id`s blindly would
   create duplicates. Entries mapped to the same id are **collapsed**: the first one is
   kept and renamed, the other entries' names are added as `type="variant"` when the
   text differs, the highest `@cert` is kept. `@target` / `@corresp` tokens that are
   mapped UUIDs are rewritten too (`linkGrp/link` stays valid); mention ids (`…-m1`)
   are never touched. In the `<text>`, only `@ref` changes (streaming, constant memory).
2. **The leading `#` is kept** (`#person-000432`). Consumers strip `^#` for lookup and
   may test `starts-with(@ref, '#work-')`, so the `#` form is the correct, safe one.
3. **Idempotent and conservative.** A second run changes nothing (`COUNT 0`); a file
   with nothing to change stays byte-identical; a header/standOff block that does not
   parse falls back to `@ref`-only rewriting with a warning. `--no-standoff` restores
   the old `@ref`-only behaviour.

Refs absent from the mapping (unreconciled or deleted entities) are left verbatim —
they keep pointing at the document's local list entry, which stays untouched. `COUNT`
reports `@ref` rewrites plus list changes.

```bash
python3 scripts/rewrite_refs.py --dry-run data/*.tei.xml   # count, write nothing
python3 scripts/rewrite_refs.py --out /tmp/preview data/*.tei.xml   # preview elsewhere
python3 scripts/rewrite_refs.py data/*.tei.xml             # in place (atomic, streaming)
```

## Configuration

Everything project-specific is an **environment variable** with a sensible default, so
the scripts run on any corpus / layout without edits.

| Variable | Used by | Default | Purpose |
|---|---|---|---|
| `TEI_GLOB` | extract | `data/LIV*_reconciled.tei.xml` | Glob of input TEI documents |
| `ENTITIES_DIR` | extract | `<dir of TEI_GLOB>/entities` | Local authority per document (`<doc>/entities_persons.csv` → `PERSnnnn`) |
| `PERSONS_CSV` | extract | empty (ignored) | `metadata_personne.csv` (PERS id, ARK, ISNI, names, dates) |
| `NER_OUT` | extract, reconcile, build, export_lots, slim_cache, finalize | `build/ner` | Intermediate artifacts + cache dir |
| `REGISTERS_DIR` | build | `data/registers` | Where the 9 registers are written |
| `ID_REGISTRY` | build | `<REGISTERS_DIR>/id_registry.csv` | Stable id registry (committed) |
| `CURATION_CSV` | build, export_lots, import_curation | `<REGISTERS_DIR>/curation.csv` (export/import: `data/registers/curation.csv`) | Curation overlay (committed) |
| `CORPUS_NAME` | build | `Grand Siecle` | Corpus name injected in register titles |
| `CORPUS_PUBLISHER` | build | `Projet Grand Siècle — UNIL / UNIGE` | `publisher` in the registers' header |
| `CORPUS_LICENCE_STATUS` | build | `free` | `availability/@status` in the registers' header |
| `CORPUS_LICENCE_URL` | build | `https://creativecommons.org/licenses/by/4.0/` | `licence/@target` (shown as "CC BY 4.0" for the default) |
| `BUILD_DATE` | build | today (ISO) | Date written in the registers' header (set it for reproducible output) |
| `WIKIDATA_CONTACT` | reconcile, build | `set-WIKIDATA_CONTACT-env` | Contact in the User-Agent (**set this**) |
| `WIKIDATA_UA` | reconcile, build | derived | Full User-Agent override |
| `WIKIDATA_API` | reconcile | `https://www.wikidata.org/w/api.php` | API endpoint (e.g. a mirror) |
| `WIKIDATA_MAXLAG` | reconcile | `5` | `maxlag` seconds (WMF politeness) |
| `WIKIDATA_WORKERS` | reconcile | `2` | Parallel API requests (keep low) |

CLI flags (not env): `reconcile_wikidata.py` takes `--min-mentions`, `--limit`,
`--types`; `rewrite_refs.py` takes `--mapping`, `--out`, `--dry-run`, `--no-standoff`;
`export_lots.py` takes `--out`, `--types`, `--min-mentions` (default 2), `--max-rows`
(default 500), `--only-new`, `--excel`, `--force`; `import_curation.py` takes
`--curation`, `--qui`, `--known-ids`, `--dry-run`.

> **Wikidata politeness:** always set `WIKIDATA_CONTACT` (or `WIKIDATA_UA`). The WMF
> policy expects a descriptive User-Agent with a contact; a missing one risks a 403.

## Team workflow (incremental curation)

Generated files are disposable and fully regenerated by each build. **Human decisions
live only in `data/registers/curation.csv`**, keyed by the stable register id kept in
`data/registers/id_registry.csv`. Commit both files; everything else is rebuilt.

```
extract → reconcile → build → export_lots → reviewers (OpenRefine / spreadsheet)
      → import_curation → build → rewrite_refs (from the ORIGINAL documents)
      ↺ repeat when documents are added or new lots are reviewed
```

```bash
# 1-3. extract, reconcile, build as usual (ids come from id_registry.csv,
#      curation.csv is re-applied)
python3 scripts/build_registers.py
# 4. export review lots (CSV), one file per type and per 500 rows
python3 scripts/export_lots.py --min-mentions 2 --out build/ner/lots
# 5. reviewers edit the lots (see the reviewer kit below), then:
python3 scripts/import_curation.py --qui "Alice" --known-ids data/registers/id_registry.csv \
  --dry-run lots_alice/*.csv        # summary only
python3 scripts/import_curation.py --qui "Alice" --known-ids data/registers/id_registry.csv \
  lots_alice/*.csv                  # writes data/registers/curation.csv
# 6. rebuild: decisions applied, ids unchanged
python3 scripts/build_registers.py
# 7. rewrite a fresh copy of the ORIGINAL documents with the new mapping
python3 scripts/rewrite_refs.py --out data/rewritten originals/*.tei.xml
# 8. check (deleted entities keep local refs: add them to --ignore-ref if needed)
tests/validate_registers.py data/registers --docs "data/rewritten/*.tei.xml" \
  --curation data/registers/curation.csv
git add data/registers/id_registry.csv data/registers/curation.csv
```

Always rewrite **from the originals**: an already rewritten document no longer carries
the NER UUIDs, so a later merge or deletion would not reach it.

When documents are added, run the same cycle: existing entities keep their id
(`id_registry.csv`), existing decisions keep applying (`curation.csv`), and the next
export marks each lot row as `nouveau`, `modifié` or `inchangé` (`--only-new` exports
only the first two).

### Reviewer kit

Everything a reviewer needs is in [`relecteurs/`](relecteurs/):

- [`relecteurs/README.md`](relecteurs/README.md) — what to do, in short;
- [`relecteurs/guide_relecteur_openrefine.pdf`](relecteurs/guide_relecteur_openrefine.pdf)
  — the step-by-step OpenRefine guide (French, with screenshots; source
  [`docs/guide_relecteur_openrefine.md`](docs/guide_relecteur_openrefine.md));
- OpenRefine recipes to paste in *Undo / Redo → Apply*:
  [`relecteurs/recettes/debut_de_lot.json`](relecteurs/recettes/debut_de_lot.json)
  (start of a lot: reconciliation, `qid_final` column) and
  [`relecteurs/recettes/fin_de_lot.json`](relecteurs/recettes/fin_de_lot.json)
  (end of a lot, before exporting the CSV).

A plain spreadsheet works too: fill the decision columns of the lot and save as CSV
(`,`, `;` or tab separator, UTF-8 with or without BOM; `export_lots.py --excel` writes
`;` + BOM for French Excel).

### Decisions (`curation.csv`)

Columns: `id,type,decision,qid_corrige,fusion_vers,label_corrige,type_corrige,commentaire,qui,date,source`.

| `decision` | Effect at build time |
|---|---|
| *(empty)* | no decision; `label_corrige` / `type_corrige` / `commentaire` still apply |
| `ok` | assert the proposed QID whatever its confidence (confidence `curated`) |
| `corriger` | `qid_corrige` set → use that QID (its properties are fetched), confidence `curated`; `qid_corrige` empty → no QID (`rejected`) |
| `fusionner` | merge the entity into `fusion_vers` (chains A→B→C resolved, cycles reported and skipped) |
| `supprimer` | entity removed from the registers; its UUIDs are no longer mapped (refs stay local) |
| `doute` | no change, `<note type="curation">doute</note>` on the entry |

`label_corrige` (new main label) and `type_corrige` (move to another register) apply
with any decision. Errors (unknown target, cycle…) never stop the build: they are
reported.

`import_curation.py` turns each edited row into a curation row, in this order:

1. **star** (`starred` / `supprimer` truthy) or decision `supprimer` → `supprimer`;
2. decision `fusionner`, or `fusion_vers` filled without a decision → `fusionner`;
3. **`qid_final`** (OpenRefine column, a QID or a Wikidata URL): `""` = untouched (no
   information); `AUCUN` = match rejected → `corriger` without QID (when a QID was
   implied); a QID different from the implied one → `corriger` with that QID; equal to
   `qid_propose` with no decision → `ok`;
4. explicit `ok` / `corriger` / `doute` (`qid_corrige` alone → `corriger`);
5. **flag** (`flagged` / `doute` truthy) → `doute`;
6. only `label_corrige` / `type_corrige` / `commentaire` → row kept, empty decision.

Truthy = `true|1|oui|x|yes|vrai`. Rows of the same type sharing a non-empty
`label_corrige` (across all imported files) are **merged** into the one with the most
mentions (`fusionner` → that id), unless they carry an explicit decision. A new row
replaces the existing curation row with the same id; re-importing an unchanged
pre-filled lot keeps the original `qui` / `date` / `source`. `--known-ids` skips ids
that are not in `id_registry.csv`.

**Lot safety.** Reviewers edit lots in place, so `export_lots.py` only replaces the
lots listed in the previous `lots_manifest.csv` and **refuses** (unless `--force`) when
one of them was modified since it was written (mtime recorded in
`<out>/.lots_written.json`) or when a target file exists outside the manifest. The
`.lots_written.json` sidecar can be deleted safely; the check then falls back on the
manifest's mtime (less precise). Export state lives in `<NER_OUT>/lots_state.json`.

## Testing

Offline suite — no network, no dependencies:

```bash
tests/run_tests.sh
```

It runs the unit tests (extraction, reconciliation scoring, id registry, curation,
lot export/import), the rewriting invariants (`test_rewrite_refs.py`), the validator
tests (`test_validate_registers.py`) and a full offline pipeline on the synthetic
fixtures (`test_pipeline.sh`: extract → build → rewrite → validate, then corpus growth
with stable ids, curation overlay, lot export, import, rewrite from originals,
validation with `--curation`, idempotence). Add the live Wikidata check with:

```bash
RUN_NETWORK_TESTS=1 WIKIDATA_CONTACT="ci@example.org" tests/run_tests.sh
```

`tests/validate_registers.py` is also usable standalone as a health-check on real output:

```bash
tests/validate_registers.py data/registers --docs "data/*.tei.xml"
```

It verifies well-formedness, the absence of duplicate `xml:id`, `id_mapping` consistency,
and that every document `@ref` resolves (or is a still-unreconciled UUID). Header refs
to the project's own authority (`#PERSnnnn`) are skipped by default
(`--ignore-ref REGEX`, default `^PERS\d+$`); `--curation curation.csv` also checks that
every curation `id` / `fusion_vers` exists and every `decision` is valid.

## Reconciliation against other referentials

Wikidata is the default authority, but for **art-domain** entities (artworks, materials,
techniques) a specialized thesaurus such as **ArtErm** is more precise. The intended
extension is to add an `idno[@type='arterm']` alongside the Wikidata QID and treat the
art thesaurus as the priority authority for those types. See `docs/workflow.fr.md`.
